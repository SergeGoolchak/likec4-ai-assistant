# Проверка предложений

<a id="decisions"></a>
## Решения по предложениям

Каждое предложение обязано иметь непустой список источников и объяснение из четырёх частей: что меняется, почему, какой эффект, насколько ассистент уверен (плюс явные допущения, если они были сделаны). Это архитектурное ограничение самого pipeline, а не опциональная настройка — предложение без источника или объяснения технически не может быть сформировано.

Доступные действия по каждому пункту:

- **Принять** — черновик кода пойдёт в генерацию как есть.
- **Отклонить** — пункт полностью исключается из дальнейшей обработки.
- **Изменить** — вы редактируете черновик кода вручную; повторного обращения к LLM не происходит, финальный текст — ваш.
- **Перегенерировать** — точечный повторный запрос только для этого пункта (не для всей проверки заново).

Pipeline продолжится дальше (генерация → валидация → diff/preview → apply), только когда решение принято по каждому пункту без исключения.

<a id="architecture-rules-severity"></a>
## must / should

Архитектурные находки (Level 2 проверки, на основе Architecture Rules) делятся на два уровня серьёзности:

- **must** — блокирует Apply, пока находка не устранена (например через Изменить/Перегенерировать конкретного пункта).
- **should** — предупреждение. Часто это эвристики с ложноположительными срабатываниями (например лексическое сходство с уже существующим элементом) — их роль подсказать человеку, а не автоматически что-то остановить.
