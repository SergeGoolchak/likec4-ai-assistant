# Diff, Preview, Apply, Rollback, История

<a id="diff"></a>
## Diff

Показывает построчно, какие файлы и как изменятся, если нажать Apply — сравнение существующего состояния с гипотетическим слитым (существующие файлы + одобренный на предыдущем шаге код). На этом этапе ничего ещё не записано на диск. Новые архитектурные элементы попадают в отдельные новые файлы; изменения существующих элементов — точечная замена нужных строк в исходном файле, а не перезапись целиком.

<a id="preview"></a>
## Preview

Рендерит итоговые диаграммы архитектуры тем же движком, что и официальный LikeC4 CLI, — на временной копии итогового состояния. Реальные файлы проекта не читаются заново и не изменяются на этом шаге.

<a id="apply"></a>
## Apply

Финальный шаг — запись изменений на диск.

<a id="apply-gate"></a>
### Почему кнопка Apply может быть недоступна

Apply разрешён, только если:

1. Техническая валидация (Level 1: синтаксис, ссылки, дубликаты id) прошла без ошибок;
2. Не осталось неразрешённых архитектурных находок уровня `must` (Level 2).

Это не просто задизейбленная кнопка "на всякий случай" — структурно pipeline не может довести сессию до экрана Apply в невалидном состоянии: если автоматическое исправление (Repair) на предыдущих стадиях не справилось за ограниченное число попыток, pipeline останавливается раньше с явной ошибкой, не доходя до Apply вовсе.

Перед самой записью на диск ассистент дополнительно сверяет хэш каждого затрагиваемого файла с тем, каким он был на момент начала анализа. Если файл успели отредактировать вручную в промежутке — Apply откажется его перезаписывать и покажет список конфликтующих путей, а не молча затрёт чужие правки.

<a id="rollback"></a>
## Rollback

Перед каждым Apply автоматически создаётся снэпшот — полная физическая копия файлов проекта на тот момент (не git-diff — папка может вообще не быть git-репозиторием). Rollback восстанавливает это состояние: перезаписывает изменённые файлы и удаляет файлы, которых на момент снэпшота ещё не было (например, новый файл, только что созданный этим самым Apply) — то есть возвращает репозиторий byte-for-byte к прежнему состоянию, а не частично.

Rollback на экране Apply откатывает именно последний Apply этой сессии и доступен один раз — после отката повторный Rollback для той же сессии недоступен (но конкретный снэпшот всегда можно восстановить вручную через Историю).

## История

Список всех сессий анализа и всех снэпшотов проекта. Restore у любого снэпшота работает так же, как Rollback — перезаписывает и подчищает файлы до состояния на момент этого снэпшота, независимо от того, какой Apply был последним.
