# Начало работы

<a id="projects"></a>
## Проекты

Проект — это связка: локальная папка с `.c4`/`.likec4` файлами + настройки подключения к Confluence и AI-провайдеру. Один проект соответствует одной архитектуре, которую ассистент дополняет по мере запуска задач. Список проектов — стартовый экран приложения.

<a id="create-project"></a>
## Создание проекта

Нужны название и путь до локальной папки на диске. Папка может быть git-репозиторием, но это не обязательно — ассистент читает и пишет файлы напрямую, без предположений о системе контроля версий. При создании ассистент сразу пытается распарсить содержимое папки как LikeC4-модель и покажет на дашборде, сколько элементов/связей/views нашлось и есть ли диагностики.

<a id="dashboard"></a>
## Дашборд проекта

Показывает текущее состояние модели (пересчитывается при каждом заходе на экран — читает файлы заново) и служит хабом ко всем остальным экранам: настройкам Confluence/AI/Architecture Rules, запуску новой задачи, истории.

<a id="confluence"></a>
## Подключение Confluence

Нужны адрес Confluence Server/Data Center и Personal Access Token с правом чтения нужных страниц. Ассистент работает исключительно в режиме чтения — он никогда не создаёт, не редактирует и не комментирует страницы Confluence. Токен хранится локально в зашифрованном виде; после сохранения его нельзя прочитать обратно (в том числе вам самим) — только заменить новым.

<a id="ai-provider"></a>
## Подключение AI-провайдера

Работает с любым сервером, реализующим протокол OpenAI Chat Completions:

- настоящий OpenAI (`api.openai.com`) — нужен API-ключ;
- локальные/self-hosted серверы — Ollama, LM Studio, vLLM, llama.cpp server и подобные — обычно API-ключ не требуется вообще, достаточно указать адрес сервера.

Если поле адреса сервера оставить пустым, используется настоящий OpenAI. Приоритет выбора адреса: настройка проекта → серверная переменная окружения (если администратор задал её при развёртывании) → `api.openai.com` по умолчанию.

<a id="architecture-rules"></a>
## Architecture Rules

Необязательные правила для новых архитектурных элементов: обязательные метаданные, регулярное выражение для naming convention, и severity — `must` (блокирует Apply, пока не устранено) или `should` (предупреждение, финальное решение остаётся за человеком на экране Proposal). Без единого правила pipeline всё равно проверяет техническую валидность кода (синтаксис, ссылки, дубликаты id) — Architecture Rules добавляют второй, архитектурный уровень проверки.
