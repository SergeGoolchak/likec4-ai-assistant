# Pipeline и экран Анализ

<a id="new-task"></a>
## Запуск новой задачи

Единственное, что нужно указать — числовой ID страницы Confluence со спецификацией (виден в URL страницы или через "..." → "Page Information"). Дальше запускается полный процесс анализа: чтение спецификации и существующей архитектуры → построение графа → извлечение требований → сопоставление с уже существующими элементами → анализ пробелов → (при необходимости) уточняющие вопросы → предложения изменений → (после решения человека) генерация кода → двухуровневая валидация → сравнение изменений → превью → применение.

<a id="analysis-screen"></a>
## Экран Анализ

Главный блок показывает текущий этап и следующее действие. Если нужны уточнения, вопросы расположены сразу под ним. Когда предложения готовы, появится кнопка «Проверить предложения». При ошибках валидации видны конкретные файлы, строки и нарушенные правила.

Список технических этапов и журнал раскрываются отдельно. Состояние берётся с сервера; пустой список вопросов не означает, что будущий этап уже пройден. Обновления поступают через SSE; при потере соединения интерфейс сообщает об этом и дополнительно проверяет состояние раз в 5 секунд.

Вкладки задачи открывают уже доступные результаты: решения, изменения, диаграммы и применение. Недоступные разделы отмечены до завершения соответствующих этапов.

Pipeline — не линейный конвейер, а стейт-машина: прогресс сохраняется после **каждой** стадии, а не только в конце. Если процесс сервера упадёт или будет перезапущен посреди работы, сессия продолжится с последней завершённой стадии, а не с начала. То же самое происходит, если стадия завершилась ошибкой — прогресс до сбоя сохранён, и повторный запуск (например после починки настроек) продолжит именно с упавшей стадии.

Два гейта в pipeline — точки, где процесс физически останавливается и ждёт внешнего действия:

- **Уточнения от вас** — если спецификация конфликтует с существующей архитектурой или найдено несколько равновероятных трактовок, ассистент задаёт явный вопрос вместо тихого выбора по умолчанию.
- **Проверка предложений вами** — pipeline не сгенерирует код, пока по каждому предложенному изменению не принято решение (Принять/Отклонить/Изменить).
